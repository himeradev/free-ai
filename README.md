# free-ai

HTTP-обёртка над [llmf](https://github.com/MoonLite-Br/llmfree): бесплатные LLM без ключей.
При запуске скрипт проверяет каждую модель каталога коротким запросом и оставляет только те, что ответили.
Проверка повторяется каждые 30 минут.

## Установка

```bash
pip install fastapi uvicorn llmf
```

## Запуск

```bash
python main.py
```

Сервер: http://0.0.0.0:11996

Первая проверка идёт в фоне (13–50 секунд в моих запусках), всё это время сервер уже принимает запросы.
История запросов и проверок за последние 24 часа сохраняется в `stats.json` рядом со скриптом.

## Сайт

Откройте http://localhost:11996 — там адрес сервера для вставки в клиент и список моделей.
У каждой модели показаны статус, лента последних 24 часов (одна клетка — 15 минут), среднее время
ответа, число запросов и ошибок. Упавшие модели свернуты внизу, рядом текст их ошибки.

## Подключение клиента

Адрес API: `http://<хост>:11996/v1`, формат OpenAI. Ключ не нужен — подойдёт любое значение.

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:11996/v1", api_key="any")
r = client.chat.completions.create(
    model="freeai/qwen-coder",
    messages=[{"role": "user", "content": "Привет"}],
)
print(r.choices[0].message.content)
```

`stream=True` отдаёт ответ по кускам. Поддерживаются `messages` (включая роль `system`),
`max_tokens`, `temperature`, `top_p`, `response_format` с `json_object`.

## Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/` | сайт |
| GET | `/models` | список моделей и статистика за 24 часа; `?include_down=true` добавит упавшие |
| POST | `/refresh` | проверить модели заново; 409, если проверка уже идёт |
| POST | `/v1/chat/completions` | вопрос к модели, OpenAI-совместимый |
| GET | `/v1/models` | список рабочих моделей в формате OpenAI |
| GET | `/ai?request=<текст>&model=<модель>` | то же самое простым GET |

`model` можно писать тремя способами: `provider/model` (`freeai/qwen-coder`), имя провайдера
(`ch-at`, возьмёт его модель по умолчанию) или короткий id, если он уникален (`qwen7b`).
`model=auto` или пустое значение — llmf сам перебирает провайдеров и берёт первый ответ.

Ошибки: 400 — неизвестная модель или неверный запрос, 502 — модель не ответила,
503 — модель отмечена как упавшая при проверке.

## Настройка через переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `HOST` | `0.0.0.0` | интерфейс |
| `PORT` | `11996` | порт |
| `RESCAN_MINUTES` | `30` | как часто перепроверять модели |
| `PROBE_TIMEOUT` | `30` | таймаут одного проверочного запроса, секунды |
| `LIVE` | выкл | `LIVE=1` — проверять ещё модели, которые провайдеры отдают через `/models`, но которых нет в каталоге |
| `STATS_FILE` | `stats.json` рядом со скриптом | где хранить историю за 24 часа |

## Что знать

- Модели у `chatai` и `notrack` не проверяются нарочно: у провайдеров дневной лимит запросов.
  На сайте они помечены «Без проверки» и остаются доступными для запросов.
- Провайдеры с дневным или почасовым лимитом (`llm7`, `blockrun`) могут исчерпать его от проверок
  и запросов — тогда модель падает до следующей проверки.
- Вызов инструментов (`tools`) передаётся в llmf как есть, но успешный вызов не подтверждён:
  `ch-at` ответил «Tool calling is not supported», остальные модели не проверялись.
